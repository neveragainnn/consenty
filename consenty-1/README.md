# consenty — конструктор макетов

Сайт с интерактивным конструктором: покупатель выбирает изделие, загружает фото, двигает/масштабирует/поворачивает/кадрирует его, добавляет надписи, видит результат на изделии и отправляет заказ. Владелец получает в Telegram сообщение с данными заказа, превью и готовый PNG-файл для печати.

Стек: **Next.js (App Router) + TypeScript**, **Tailwind CSS 4**, **Konva / react-konva** (редактор), **zustand** (состояние редактора), **zod** (валидация), **S3-совместимое хранилище** (AWS S3, Cloudflare R2, Yandex Object Storage, MinIO…), **Telegram Bot API**, **Vitest**.

## Как работает связка с Авито

Заказ и переписка — на Авито. Сайт нужен только для макета:

1. Покупатель собирает макет и вводит **имя, как в профиле Авито** (и по желанию комментарий).
2. Сайт показывает **код макета** из 5 символов (например, `K7QXP`) и просит прислать его в чате Авито.
3. В Telegram приходит: превью на изделии, сообщение с кодом и именем, **файл печати** и **оригиналы фото** покупателя (документами, без сжатия).
4. Код из чата Авито ищется поиском в Telegram — так видно, чей это макет.

Все файлы макета также лежат в хранилище: `orders/<код>/`.

## Запуск, чтобы сайтом могли пользоваться покупатели

Макеты отправляются **прямо в Telegram** — хранилище файлов не нужно. Нужно только:

### 1. Бот в Telegram (с телефона)
1. @BotFather → `/newbot` → имя → адрес, оканчивающийся на `bot` → получите **токен**.
2. Откройте своего бота и напишите ему любое сообщение.
3. В браузере откройте `https://api.telegram.org/botТОКЕН/getUpdates` и найдите `"chat":{"id":…}` — это **ID чата**.

### 2. Загрузить проект на GitHub (в браузере, без программ)
1. Зарегистрируйтесь на github.com → **New repository** → имя `consenty` → **Create**.
2. Нажмите **uploading an existing file** и перетащите файлы из распакованной папки.
   GitHub принимает до 100 файлов за раз, поэтому в два захода: сначала всё, кроме папки `src`, затем — папку `src`.
   После каждого захода нажмите **Commit changes**.

### 3. Опубликовать на Vercel
1. vercel.com → **Sign up with GitHub** → **Add New → Project** → выберите `consenty` → **Import**.
2. Раскройте **Environment Variables** и добавьте две переменные:
   - `TELEGRAM_BOT_TOKEN` — токен бота;
   - `TELEGRAM_CHAT_ID` — ID чата.
3. **Deploy**. Через пару минут сайт будет доступен по адресу вида `consenty.vercel.app`.

### 4. Проверка
Откройте сайт с телефона, соберите макет, нажмите «Отправить макет продавцу». В Telegram придут: сообщение с кодом и именем с Авито, превью, файл печати и оригиналы фото.

Если позже захотите хранить копии макетов ещё и в облаке — подключается S3-хранилище (см. «Хранилище файлов» ниже), но для работы это не обязательно.

## Быстрый старт

Требуется Node.js 20.9+.

```bash
npm install
cp .env.example .env.local     # можно оставить пустым — всё заработает в демо-режиме
npm run dev                    # http://localhost:3000
```

Без настроек сайт полностью работает локально:

- конструктор, превью и экспорт — в браузере;
- файлы заказов сохраняются в папку `.data/` (вместо S3);
- Telegram не настроен — заказ сохраняется, а на странице успеха и в форме заказа честно показано, что уведомление **не отправлено** и что нужно добавить.

Проверки:

```bash
npm run typecheck   # next typegen + tsc
npm test            # vitest: заказы, валидация файлов, Telegram, API
npm run build       # production-сборка
npm run check       # всё сразу
```

## Как устроен конструктор

- **Единицы дизайна = пиксели производственного файла.** Для каждой стороны товара из `PrintSpec` (мм + DPI) вычисляется размер файла: область печати + вылеты. Все слои хранят координаты в этих пикселях; редактор лишь масштабирует вид. Поэтому экспорт — это рендер 1:1 без пересчётов.
- **Одни и те же атрибуты Konva** (`src/lib/design/layers.ts`) используются и в редакторе, и при экспорте — файл печати совпадает с тем, что видно на экране.
- Фото рисуется дважды: полупрозрачный «призрак» за пределами области (за него можно тянуть) и чистая копия, обрезанная по области печати.
- Направляющие: линия реза (оранжевая), безопасная зона (пунктир), вылеты (белый пунктир). Центр фото нельзя увести за область печати; если фото не закрывает область, сильно вылезает или растянуто (низкий DPI), рамка краснеет и появляется предупреждение. Текст вне безопасной зоны тоже даёт предупреждение.
- Жесты: перетаскивание пальцем/мышью, масштаб и поворот двумя пальцами, ручки трансформации, ползунки (масштаб, поворот, положение), кнопки «Заполнить», «Вписать», «По центру», «90°», кадрирование с пресетами, замена/удаление, отмена/повтор (`Ctrl+Z`, `Ctrl+Shift+Z`), сброс, переключение сторон, надписи (шрифт, размер, цвет, поворот).
- Режим «На изделии» показывает чистый предпросмотр без элементов редактора.

### Реалистичный mockup

`src/lib/mockup/render.ts`: принт натягивается на четырёхугольник области печати через **гомографию** (перспективное преобразование, сетка треугольников), обрезается **маской** (скруглённый контур в перспективе или ваша PNG-маска), поверх кладутся **блики** (`overlay`, режим `screen`), сквозь принт слегка проступает фактура подложки (`materialStrength`).

Это визуальная аппроксимация для плоской поверхности, а не физическая симуляция материала.

### Экспорт

- **Файл печати**: PNG с прозрачным фоном в точном размере области печати + вылеты при заданном DPI. Без направляющих и лишних деталей.
- **Превью**: PNG дизайна на изделии.
- **Оригинал фото** хранится отдельно, без изменений.

Все три файла хранятся раздельно: `orders/<id>/print-front.png`, `preview-front.png`, `original-front.jpg` (и `-back` для второй стороны).

## Товары, цены и mockup

Всё в `src/config/products.ts`. Размеры принта картхолдера (90 × 59 мм) и металлической зажигалки (32 × 51 мм) — реальные. **Цены пока демонстрационные** (`priceIsDemo: true`) — замените, и пометки исчезнут.

Добавить товар — добавить объект в `PRODUCTS`: название, цену, доплату за вторую сторону, варианты (цвета) и стороны. У каждой стороны:

```ts
{
  label: "Лицевая",
  print: { widthMm, heightMm, bleedMm, safeMm, cornerRadiusMm, dpi, isDemo },
  editor: {                         // плоское фронтальное изображение для редактора
    image: "/mockups/my-flat.png",
    imageMm: [98, 66],              // размер всего изображения в мм
    trimOffsetMm: [6, 6],           // где на нём левый верхний угол области печати
  },
  mockups: [                        // один или несколько ракурсов превью; первый уходит в заказ
    {
      kind: "quad2d",
      label: "Закрыт",                  // подпись в переключателе ракурсов
      image: "/mockups/my-photo.jpg",
      overlay: "/mockups/my-gloss.png", // необязательно: блики с прозрачностью
      mask: "/mockups/my-mask.png",     // необязательно: белое — где принт виден
      width: 2000, height: 2000,        // размер фото в px
      quad: [ {x,y}, {x,y}, {x,y}, {x,y} ] // углы области печати: ВЛ, ВП, НП, НЛ
    },
  ],
}
```

### Как заменить демо-mockup на реальные фотографии

Сейчас все товары показаны на реальных фото (`public/mockups/photo/`), подготовленных скриптами `scripts/build-photo-mockups*.py`. Чтобы подставить новые фото:

1. Сфотографируйте изделие с нужного ракурса (ровный свет, однотонный фон). Положите в `public/mockups/`.
2. Откройте фото в любом редакторе, наведите курсор на 4 угла поверхности печати и выпишите координаты в пикселях — это `quad`.
3. Для изогнутых краёв или выступов сделайте PNG-маску того же размера: белым — где принт виден, прозрачным — где нет.
4. Для бликов сделайте PNG того же размера: блики на прозрачном фоне.
5. Для редактора нужна фронтальная («плоская») фотография или рендер и положение области печати на ней в мм.

Отдельные изображения для цвета корпуса задаются в `variants[].images`.

### Задел для 3D

Поле `mockup.kind` и интерфейс `MockupImages/DesignSource` оставлены для других рендереров. Для 3D (Three.js): экспортированный холст стороны (`renderSideCanvas`) используется как текстура материала на модели, а компонент превью выбирает рендерер по `kind`. Редактор и экспорт менять не придётся.

## Telegram

1. Напишите [@BotFather](https://t.me/BotFather) → `/newbot` → получите токен.
2. Напишите своему боту любое сообщение (или добавьте бота в группу и напишите там).
3. Откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id": ...}` — это `TELEGRAM_CHAT_ID` (у групп он отрицательный).
4. Заполните в `.env.local` (локально) или в настройках Vercel:

```
TELEGRAM_BOT_TOKEN=123456:ABC...
TELEGRAM_CHAT_ID=123456789
```

Что приходит на каждый заказ:

1. Превью (одно фото или альбом из двух сторон) с номером заказа.
2. Сообщение: номер, дата, товар и цвет, стороны, количество, сумма, имя, контакт, комментарий, временные ссылки на макет печати, оригинал и превью.
3. PNG-файлы печати документами (без сжатия Telegram).

Надёжность: тайм-аут на запрос, до 3 попыток с экспоненциальной задержкой и учётом `retry_after` при 429. Каждый успешный шаг записывается в заказ, поэтому повторная отправка (через `/order/error` или повторный запрос клиента) **не дублирует** сообщения. Токен существует только на сервере и не попадает в логи.

## Хранилище файлов

Файлы идут **напрямую из браузера в хранилище** по подписанным ссылкам — это обходит лимит размера тела запроса serverless-функций (4,5 МБ на Vercel).

```
S3_BUCKET=my-print-orders
S3_ACCESS_KEY_ID=...
S3_SECRET_ACCESS_KEY=...
S3_REGION=auto                         # R2: auto, Yandex: ru-central1, AWS: eu-central-1
S3_ENDPOINT=https://<id>.r2.cloudflarestorage.com   # для AWS не нужен
```

Бакет должен быть **приватным**. Настройте CORS, чтобы браузер мог загружать файлы:

```json
[
  {
    "AllowedOrigins": ["https://ваш-домен.ru", "http://localhost:3000"],
    "AllowedMethods": ["PUT"],
    "AllowedHeaders": ["Content-Type"],
    "MaxAgeSeconds": 3600
  }
]
```

Структура бакета:

```
tmp/<uploadId>/...          временные загрузки (до создания заказа)
orders/<id>/order.json      данные заказа
orders/<id>/print-*.png     файлы печати
orders/<id>/preview-*.png   превью
orders/<id>/original-*.*    оригиналы фото
idempotency/<hash>.json     защита от дублей
```

### Очистка временных файлов

- `GET /api/cron/cleanup` удаляет из `tmp/` всё старше `TMP_FILES_TTL_HOURS` (24 ч). На Vercel он запускается ежедневно через `vercel.json` (нужна переменная `CRON_SECRET`).
- Дополнительно рекомендуется правило жизненного цикла в бакете: удалять `tmp/` через 1 день, `idempotency/` — через 30 дней.
- Заказы (`orders/`) автоматически не удаляются — решите сами, сколько хранить персональные данные, и добавьте правило.

## Безопасность

- Цена и параметры товара **всегда пересчитываются на сервере** из `products.ts`; клиентские значения игнорируются.
- Файлы проверяются дважды: метаданные (MIME, расширение, размер) — при выдаче ссылок, реальные размер и сигнатура байтов — при создании заказа. SVG, HEIC, GIF и прочее не принимаются.
- Набор файлов заказа подписан HMAC-«билетом» (`ORDER_SIGNING_SECRET`): нельзя подставить чужие ключи или файлы.
- Идемпотентность: атомарная условная запись (`If-None-Match: *` в S3, флаг `wx` локально). Двойное нажатие, повтор после обрыва связи и параллельные запросы дают один заказ.
- Ограничение частоты запросов на эндпоинтах + поле-ловушка для ботов. Ограничитель хранится в памяти инстанса — для серьёзной нагрузки подключите Vercel Firewall или Upstash Ratelimit.
- Персональные данные не публикуются: нет публичных списков заказов, файлы приватные, ссылки временные (до 7 суток). Повтор уведомления доступен только автору заказа.
- Оплата **не принимается автоматически**: после заказа покупатель видит, что с ним свяжутся для подтверждения и оплаты. Статуса «оплачено» нет.

## Публикация на Vercel

1. Загрузите проект в GitHub (файлы `.env*` в `.gitignore`).
2. В Vercel: **Add New → Project** → выберите репозиторий. Настройки сборки определятся автоматически.
3. **Settings → Environment Variables**: добавьте `TELEGRAM_*`, `S3_*`, `ORDER_SIGNING_SECRET` (`openssl rand -hex 32`), `CRON_SECRET`.
4. Deploy. После публикации добавьте домен сайта в CORS бакета.

Без `S3_*` на Vercel заказы не принимаются (файловая система там временная) — форма покажет понятное сообщение, а конструктор продолжит работать.

```
    editor/               конструктор: холст, панели, кадрирование, превью

  lib/
    design/               состояние редактора, слои, экспорт, загрузка фото

tests/                    vitest
scripts/build-photo-mockups*.py  подготовка фото-mockup и карт освещения
```
